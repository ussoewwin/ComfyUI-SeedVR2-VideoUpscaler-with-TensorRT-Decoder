# ComfyUI 云环境依赖错误完整说明

本文完整说明在 Vast.ai、RunPod 等云环境中运行 SeedVR2（以及其他依赖较重的自定义节点）时常见的 `ModuleNotFoundError`：根因是什么，以及本仓库在代码层面实现的自动修复如何工作。

---

## 1. 错误现象与发生方式

**[错误]**
```python
ModuleNotFoundError: No module named 'diffusers'
ModuleNotFoundError: No module named 'rotary_embedding_torch'
```

即使用户刚在 Vast.ai 终端执行过 `pip install diffusers`，并看到 **"Successfully installed"**，ComfyUI 加载 SeedVR2 时仍可能出现上述错误。

### 核心原因（两个因素叠加）

该错误是 ComfyUI 的设计哲学与云环境模板结构发生“完美风暴”的结果。

#### 因素 A：ComfyUI 的“反膨胀”哲学

在 AI 图像生成生态中，`diffusers`、`transformers`、`accelerate` 等库是**行业标准**（Automatic1111 也依赖它们）。  
但 ComfyUI 的设计方向相反：追求精简、快速、以原生 PyTorch 为主，避免厚重抽象与膨胀。因此 **ComfyUI 故意不把 `diffusers` 等放入官方核心依赖**。  
结果是，云平台提供的“干净” ComfyUI 环境默认不会安装这些库。

#### 因素 B：看不见的多重 Python 环境

Vast.ai 上的 ComfyUI 模板通常把计算环境分成多层：

1. **终端（面向用户）**：系统 Python（例如 `/usr/bin/python`）。
2. **ComfyUI 执行进程**：隐藏的虚拟环境（例如 `/workspace/ComfyUI/venv/bin/python`）。

用户在终端输入 `pip install` 时，命令总是打到“系统”环境；而 ComfyUI 实际用“执行进程”环境加载节点。用户很难从 UI 精确指向隐藏 venv，手工安装落错位置，于是出现 `ModuleNotFoundError`。

---

## 2. 解决方案（代码修改细节）

为突破上述陷阱，本仓库对 SeedVR2 的启动入口（`__init__.py`）做了大幅修改。

**修改文件：** `/ComfyUI/custom_nodes/ComfyUI-SeedVR2_VideoUpscaler/__init__.py`

### 实现细节

```python
import sys
import subprocess

def ensure_package(package_name, import_name=None):
    if import_name is None:
        import_name = package_name.split(">")[0].split("=")[0].split("<")[0]
    
    try:
        # First, attempt to actually import the module
        __import__(import_name)
        return  # Already available
    except (ImportError, ModuleNotFoundError):
        pass
    
    # Package is missing - install it
    print("\n" + "="*80)
    print(f"SeedVR2: '{import_name}' module not found.")
    print(f"SeedVR2: Current Python executable: {sys.executable}")
    print(f"SeedVR2: Attempting automatic installation of {package_name}...")
    try:
        subprocess.check_call([sys.executable, '-m', 'pip', 'install', package_name])
        print(f"SeedVR2: Successfully installed {package_name}")
    except Exception as e:
        print(f"SeedVR2: Auto-installation failed: {e}")
    print("="*80 + "\n")

# Register all dependencies from requirements.txt for auto-installation
_REQUIRED_PACKAGES = [
    ("safetensors", None),
    ("tqdm", None),
    ("omegaconf>=2.3.0", "omegaconf"),
    ("diffusers>=0.33.1", "diffusers"),
    ("transformers", None),
    ("accelerate", None),
    ("peft>=0.17.0", "peft"),
    ("rotary_embedding_torch>=0.5.3", "rotary_embedding_torch"),
    ("opencv-python", "cv2"), # Mapping pip name to import name
    ("gguf", None),
]

for pkg, imp in _REQUIRED_PACKAGES:
    ensure_package(pkg, imp)
```

---

## 3. 为何这样能奏效

以下说明该代码如何解决环境不一致问题。

### 1. 用 `sys.executable` 定位“真正路径”

修复的关键是使用 `sys.executable`。  
`sys.executable` 指向**当前正在执行该脚本的 Python 解释器的精确路径**（即运行 ComfyUI 的隐藏 `venv` 路径）。

通过 `subprocess.check_call([sys.executable, '-m', 'pip', 'install', package_name])`，完全绕过终端环境，**强制把包装进当前活跃的 ComfyUI 虚拟环境**，从而解决“看不见的安装目标”问题。

### 2. 用 `try / __import__()` 可靠检测

`importlib.find_spec()` 在包损坏、半安装时可能假阳性。  
用真正的 `__import__()` 包在 `try/except` 中，可保证仅在模块确实无法加载（`ModuleNotFoundError`）时才触发自动安装。

### 3. 处理 pip 名与 import 名不一致

部分包的 pip 名与 import 名不同（例如 `pip install opencv-python` vs `import cv2`）。  
`_REQUIRED_PACKAGES` 显式拆分“pip 包名”与“import 检查名”，避免假阴性导致的无限安装循环。

### 总结

有了本次更新，即便在 Vast.ai / RunPod 上通过 `git clone` 手动安装 SeedVR2，也会在 ComfyUI 启动时自愈：扫描内部环境、发现缺失依赖，并精确安装到正确位置，用户无需再排查隐藏的 Python 路径。
