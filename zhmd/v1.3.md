**标签：** `v1.3`  
**提交：** `0628cb0`（性能相关工作在 `5f2a472`）  
**日期：** 2026-07-28

本版本聚焦 ComfyUI SeedVR2 路径在 Windows 上的 **torch.compile / inductor 运行时改进**：在 **win32 上启用并行 inductor 编译**；在每个阶段的首个 batch 之后关闭 compile worker，使其不再长期占用 CUDA 上下文；在单次运行期间启用 **`cudnn.benchmark`**；并使 VAE 时序切片更均匀，以减少编译形状变体。

**指南（完整说明）：**  
- https://github.com/ussoewwin/ComfyUI-SeedVR2_VideoUpscaler/blob/main/md/SEEDVR2_SPEED_VRAM_HEADROOM.md  
- https://github.com/ussoewwin/ComfyUI-SeedVR2_VideoUpscaler/blob/main/md/SEEDVR2_WINDOWS_PARALLEL_COMPILE_FIX.md

---

## 1. 摘要

| 主题 | 状态 |
|------|------|
| **Windows 编译瓶颈** | 库存 torch 在 `win32` 上强制 `compile_threads = 1`，冷缓存 inductor/Triton 编译串行，可能让 GPU 空闲数分钟 |
| **并行编译修复** | `fix_inductor.py` 在 Windows 上改为 `worker_start_method = "spawn"` 与 `compile_threads = min(8, cpu_count)`（除非设置了环境变量覆盖） |
| **Worker 显存滞留** | spawn worker 在 autotune 基准后可能继续持有 CUDA 上下文 |
| **Worker 清理修复** | `generation_phases.py` 在每个阶段首个 batch 之后调用 `shutdown_compile_workers()`（该阶段编译工作已完成） |
| **VAE 卷积速度** | `video_upscaler.py` 仅在本次运行期间将 `torch.backends.cudnn.benchmark = True`，随后恢复调用方原设置 |
| **编译形状稳定性** | `attn_video_vae.py` 单独处理首帧/首 latent，其余按均匀 ACTIVE 块处理，减少 first/rest 形状族分裂 |

## 2. 变更内容

### 2.1 Windows 上的并行 inductor 编译

- 在 `src/core/fix_inductor.py` 中新增 `_patch_inductor_parallel_compile_windows()`
- 在不改变 Linux 行为的前提下启用 Windows 并行编译
- 尊重：
  - `TORCHINDUCTOR_COMPILE_THREADS`
  - `TORCHINDUCTOR_WORKER_START`
- 在自定义节点 import 时由 `_fix_inductor_windows_encoding()` 应用

### 2.2 首个 batch 之后释放 compile worker

- 在 `src/core/generation_phases.py` 中新增 `_shutdown_inductor_compile_workers()` 辅助函数
- 每个阶段在首个 batch 之后调用一次：
  - encode
  - DiT upscale
  - decode
- 目的：在后续 batch 与下一阶段之前，释放空闲 compile worker 持有的 CUDA 上下文与显存

### 2.3 为本次运行启用 cuDNN autotuner

- `src/interfaces/video_upscaler.py` 现在：
  1. 保存当前的 `torch.backends.cudnn.benchmark`
  2. 在运行中设为 `True`
  3. 在 `finally` 中恢复原值
- 从而在无需全局 ComfyUI 启动标志的情况下，为 ComfyUI 路径提供与实用 VAE 卷积 autotune 相近的收益

### 2.4 VAE 中更均匀的时序切片

- `src/models/video_vae_v3/modules/attn_video_vae.py`
- 首帧/首 latent 单独以 `INITIALIZING` 处理
- 其余块以均匀 `ACTIVE` 块处理
- 相对旧的 first/rest 切分，减少编译形状碎片化

## 4. 预期效果

- 相对库存串行路径，Windows 上冷缓存编译更快
- 各阶段首个 batch 之后，空闲 compile worker 占用更少显存
- 正常运行中 VAE 卷积性能更好
- 因不均 first/rest 时序切片导致的可避免编译变体更少

本版本改进的是 **compile 周边的运行时行为**，而非模型权重本身。
