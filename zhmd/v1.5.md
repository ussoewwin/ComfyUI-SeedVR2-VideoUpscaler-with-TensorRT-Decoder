**标签：** `v1.5`  
**范围：** TensorRT VAE 解码器集成与执行管线  
**日期：** 2026-09-03  

本版本为 ComfyUI 中的 SeedVR2 引入了专用的 **TensorRT VAE 解码器（Decoder）**加速，在 VAE 解码阶段（Phase 3）实现显著的速度提升（2x–5x 加速），同时保持严格的数学重构一致性与显存（VRAM）安全性。

本仓库中的 TensorRT VAE 后端架构灵感来源于 [VRGDG-SeedVR2-TensorRT-Studio](https://github.com/vrgamegirl19/VRGDG-SeedVR2-TensorRT-Studio)（基于 Apache 2.0 许可证）。

---

## 1. 变更摘要

| 组件 / 特性 | 实现细节 |
|---|---|
| **专用解码器加载节点** | 在 `SEEDVR2` 类别下新增 `SeedVR2LoadTensorRTVAEDecoder` 节点，实现编码器与解码器引擎配置解耦 |
| **放大节点输入解耦** | `SeedVR2VideoUpscaler` 主节点新增独立的 `vae_encode` 与 `vae_decode` 自定义输入插槽 |
| **引擎规格自动发现** | 动态扫描 `tensorrt_backend/artifacts/` 中的 `vae_decoder_tile_*_*f.rtxplan` 引擎，自动填充 4n+1 帧长下拉选项 |
| **多 Tile 与 Studio Overlap 对齐** | 支持 512px Tile（tile=64, overlap=24）与 256px Tile（tile=32, overlap=12），具有 Studio 兼容的空间羽化融合与 `clamp(-2.0, 2.0)` 输出限制 |
| **执行上下文缓存复用** | 跨 Chunk 缓存反序列化的 CUDA 引擎、执行上下文（Execution Context）与 CUDA 流，彻底消除每 Chunk 约 4.5GB 显存的重复创建开销 |
| **任意帧长分块处理** | 自动将任意长度的 4n+1 Latent 视频序列拆分为引擎规格窗口，以 1 Latent 帧（4 视频帧）重叠平滑拼接 |
| **安全回退机制** | 缺失 TRT 引擎时，自动无缝回退至 PyTorch 标准 VAE，并支持独立配置的分块解码（`Fallback: Decode Tiled`、Tile Size、Overlap） |
| **彻底的显存释放** | 通过 `release()`（`gc.collect()` + `torch.cuda.synchronize()` + 两次 `empty_cache()`）在阶段结束时彻底释放 VRAM |

## 2. 技术架构与代码实现细节

### 2.1 专用解码器加载节点（`SeedVR2LoadTensorRTVAEDecoder`）
位于 `src/interfaces/trt_vae_model_loader.py`：
- **节点 ID：** `SeedVR2LoadTensorRTVAEDecoder`
- **类别：** `SEEDVR2`
- **输出：** `SEEDVR2_VAE`（专为 Phase 3 解码阶段配置）
- **输入参数：**
  - `model`：标准 VAE 权重（如 `ema_vae_fp16.safetensors`），用于回退初始化
  - `device`：推理 GPU 设备（`cuda:0`）
  - `Fallback: Decode Tiled`、`Fallback: Decode Tile Size`、`Fallback: Decode Tile Overlap`：仅在 TRT 引擎缺失且进入回退模式时生效的 PyTorch 分块参数
  - `engine_frames`：自动填充的下拉菜单，展示可用的 4n+1 帧规格（`auto`、`29`、`21`、`5` 等）

### 2.2 TensorRT 解码器执行管线（`src/core/trt_decoder.py`）
- **引擎搜索与选择（`find_engine_path`）**：
  检索 `tensorrt_backend/artifacts/` 和 `ComfyUI/models/tensorrt/seedvr2/`。
  优先使用 512px Tile 引擎（`vae_decoder_tile_512_{N}f.rtxplan`），次选 256px Tile 引擎（`vae_decoder_tile_256_{N}f.rtxplan`）。
- **上下文缓存（`_engine`）**：
  一次反序列化引擎并将执行上下文保留在 `_DECODER_ENGINES` 缓存中。上下文复用消除了多 Chunk 处理时昂贵的 CUDA 驱动分配开销。
- **空间分块与羽化融合（`_decode_single_chunk`）**：
  将 Latent 空间维度填充至 Tile 整数倍，通过专用 CUDA 流异步执行各 Tile 推理，应用方向线性羽化权重（`_feather`），按重叠权重归一化，并在转换为目标数据类型前将数值限制在 `[-2.0, 2.0]`。
- **时序分块解码（`_decode_chunked` / `src/core/infer.py`）**：
  当 Latent 帧数超过引擎单次处理能力时，Latent 张量按步长（`lat_stride = engine_latent - 1`）切分为重叠子块，解码后的视频片段按时序边界无缝拼接。

### 2.3 工作流输入解耦（`src/interfaces/video_upscaler.py`）
`SeedVR2VideoUpscaler` 节点将 VAE 输入分离为 `vae_encode` 与 `vae_decode`。这允许工作流在 Phase 1 使用轻量 PyTorch VAE 编码，在 Phase 3 使用超高速 TensorRT 解码，在兼顾易用性的同时实现最大的解码吞吐。

## 3. 本版本涉及的代码面

| 文件路径 | 作用与变更 |
|---|---|
| `src/core/trt_decoder.py` | 核心 TensorRT VAE 解码引擎、缓存管理、空间分块、时序切分与显存释放 |
| `src/interfaces/trt_vae_model_loader.py` | `SeedVR2LoadTensorRTVAEDecoder` 节点实现与引擎自动发现 |
| `src/interfaces/trt_vae_builder.py` | TensorRT 引擎显式构建节点接口 |
| `src/interfaces/video_upscaler.py` | `vae_encode` / `vae_decode` 双插槽路由与执行调度 |
| `src/core/infer.py` | TRT VAE 批次的步长对齐、分块分发与空间尺寸对齐 |
| `__init__.py` | 注册 `SeedVR2LoadTensorRTVAEDecoder` 节点与启动时引擎就绪检测 |
| `example_workflows/SeedVR2_tensorrt_decode.json` | 包含 TensorRT VAE 解码器与 2 次放大管线的完整示例工作流 |

## 4. 验证与一致性

- **数学一致性**：分块与融合算法与 Studio TensorRT 引擎保持严格的像素级重构一致性。
- **显存稳定性**：上下文缓存避免了 GPU 显存泄漏；`release()` 确保生成任务结束后 GPU 显存即时清零。
- **回退可靠性**：在非 NVIDIA GPU 或未构建 TensorRT 引擎的环境中，工作流将安全透明地回退至标准 PyTorch VAE 执行。
