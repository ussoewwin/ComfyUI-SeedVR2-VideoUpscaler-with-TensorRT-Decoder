**标签：** `v1.4`  
**代码提交：** `2f90466`（3B registry + durable NVFP4 autocast skip）  
**文档：** `525de59`（指南）、`3c78610`（changelog）  
**日期：** 2026-07-31

本版本将 **3B** HSWQ INT8 ConvRot 与 NVFP4 DiT 权重包按与 7B 相同的方式登记到 registry；通过 registry 规格选择 3B/7B 配置目录；并新增 **durable** 的 `runner._dit_is_nvfp4`，使 materialize 清空 `_dit_checkpoint` 之后，NVFP4 仍可正确跳过 autocast。

## 1. 摘要

| 主题 | 状态 |
|------|------|
| **3B INT8 ConvRot 权重包** | 登记为 `seedvr2_3b_int8_convrot.safetensors`（`precision="int8_tensorwise_convrot"`） |
| **3B NVFP4 权重包** | 登记为 `seedvr2_3b_nvfp4.safetensors`（`precision="nvfp4"`） |
| **原生显存路径** | 架构不变：基于内容的 `*.comfy_quant` + 构建时 `comfy.ops.mixed_precision_ops`（与 7B 相同） |
| **配置目录选择** | `_create_new_runner` 改用 `resolve_dit_config_folder()`，不再仅用 `"7b" in dit_model` |
| **NVFP4 autocast 缺陷** | 跳过逻辑依赖 `_dit_checkpoint`，而 materialize 后该字段为 `None`，导致跳过从未生效 |
| **Durable 修复** | 新增 `runner._dit_is_nvfp4`，在路径清空后仍保留；upscale 阶段只读该标志 |

示例模型文件：

- `models/SEEDVR2/seedvr2_3b_int8_convrot.safetensors`
- `models/SEEDVR2/seedvr2_3b_nvfp4.safetensors`

## 2. 变更内容

### 2.1 在 `MODEL_REGISTRY` 中登记 3B INT8 / NVFP4

`src/utils/model_registry.py`：

```python
    # HSWQ INT8 / NVFP4 (native VRAM path; same as 7B)
    "seedvr2_3b_int8_convrot.safetensors": ModelInfo(size="3B", precision="int8_tensorwise_convrot"),
    "seedvr2_3b_nvfp4.safetensors": ModelInfo(size="3B", precision="nvfp4"),
```

使 3B 权重包成为正式 DiT 条目，并让 `resolve_dit_config_folder()` 可通过 `size="3B"` 选择 `configs_3b`。仅登记 registry **不会**实现量化；打包显存仍依赖内容检测 + 构建时 ops。

### 2.2 通过 registry 解析配置目录

`src/core/model_configuration.py` 的 `_create_new_runner`：

**之前：** `'./configs_7b' if "7b" in dit_model else './configs_3b'`  
**之后：** `resolve_dit_config_folder(os.path.basename(dit_model))`

解析顺序：registry `size` → 文件名中的 `7b`/`3b` → 默认 `configs_3b`。

### 2.3 Durable `_dit_is_nvfp4` 用于 autocast 跳过

**缺陷：** 权重加载后，`materialize_model` 将 `runner._dit_checkpoint = None`。upscale 阶段原先使用：

```python
nvfp4_native = (
    bool(getattr(runner, "_dit_comfy_quant_native", False))
    and checkpoint_is_nvfp4(getattr(runner, "_dit_checkpoint", None))
)
```

因此推理时 `checkpoint_is_nvfp4(None)` 恒为 false。autocast 可能启用 → LayerNorm/RMSNorm → float32 → `comfy_kitchen` 的 `quantize_nvfp4` 拒绝 float32（仅接受 FP16/BF16）。该问题同时影响 **7B 与 3B** NVFP4。

**修复：**

1. `prepare_model_structure`（`model_loader.py`）：

```python
runner._dit_is_nvfp4 = bool(create_kwargs) and checkpoint_is_nvfp4(checkpoint_path)
```

2. Upscale（`generation_phases.py`）：

```python
nvfp4_native = bool(getattr(runner, "_dit_is_nvfp4", False))
use_autocast = (
    not nvfp4_native
    and dit_dtype != ctx['compute_dtype']
    and ctx['dit_device'].type != 'mps'
)
```

3. DiT 缓存复用（`model_configuration.py`）从恢复的 checkpoint 路径重新计算 `_dit_is_nvfp4` / `_dit_comfy_quant_native`。

仅靠 `_dit_comfy_quant_native` 不够：INT8 native 也会设置它；autocast 跳过是 NVFP4 专用逻辑。

## 4. 预期效果

- 3B INT8 ConvRot / NVFP4 作为已登记 DiT，并正确使用 `configs_3b`
- 存在 `*.comfy_quant` 时，原生打包显存路径继续工作（加载架构不变）
- materialize 之后 NVFP4 upscale 不再丢失 autocast 跳过（7B 与 3B）
- 缓存复用时 native-quant 标志保持一致
