**标签：** `v1.5.3`
**范围：** 暂停 TensorRT VAE 编码器（左上角分块伪影未解决），并将 FP16 VAE 编码重构为批量模式
**日期：** 2026-09-09

本版本暂停 TensorRT VAE **编码器**，将视频编码回退至标准 FP16 VAE，同时保留 TensorRT **解码器** 完整可用。编码器的左上角分块伪影 —— 分块边缘感受野不足与填充污染叠加 —— 在 256px 或 512px 分块尺寸下均无法消除，因此编码回退至确定性的 FP16 路径。与此同时，FP16 编码路径被重构为一次性编码整个片段，取代了实际为空操作的逐帧循环。

---

## 1. 变更摘要

| 区域 | 涉及文件 | 实现细节 |
|---|---|---|
| **暂停 TensorRT VAE 编码器** | `src/interfaces/__init__.py`, `__init__.py` | 从节点注册表移除 `SeedVR2LoadTensorRTVAEModel`（编码 + 解码 TRT）。`SeedVR2LoadTensorRTVAEDecoder`（仅解码 TRT）与 `SeedVR2BuildTensorRTVAE` 仍可用。 |
| **批量 FP16 VAE 编码** | `src/core/infer.py` | `vae_encode` 现一次性编码整个片段（`[1,C,T,H,W]`），取代逐帧循环（空操作，因为批次维度恒为 1）。`slicing_encode` 以因果卷积缓存进行时间切分，保留时间上下文并移除逐帧 `empty_cache`/`gc` 开销。 |
| **TRT 编码器缓解（保留供后续使用）** | `src/core/trt_encoder.py` | 半 tile 外围填充（将图像四角置于其角落 tile 的中心）及 `set_input_shape` 后的 `torch.cuda.synchronize()`（修复间歇性首个 tile NaN）。 |

## 2. 深入剖析与架构改进

### 2.1 FP16 VAE 批量编码

旧版 `vae_encode` 使用逐帧循环编码输入片段：

```python
import gc
latent_chunks = []
num_frames = sample.size(0)          # 批次维度 = 1
for f_idx in range(num_frames):      # 实际只执行一次
    frame_sample = sample[f_idx:f_idx+1]
    frame_latent = self.vae.encode(frame_sample, tiled=..., tile_size=..., tile_overlap=...).latent
    latent_chunks.append(frame_latent)
    del frame_sample
    torch.cuda.empty_cache()
    gc.collect()
latent = torch.cat(latent_chunks, dim=0)
```

由于 `sample` 恒为 `[1,C,T,H,W]`（批次维度为 1），`sample.size(0)` 返回 `1`，循环体实际只执行一次，"逐帧" 切分从未真正发生。唯一实际效果是每次迭代冗余调用一次 `empty_cache()` + `gc.collect()`。

重构后的路径一次性编码整个片段：

```python
# sample 已经是 [1, C, T, H, W]
latent = self.vae.encode(sample, tiled=self.encode_tiled,
                         tile_size=self.encode_tile_size,
                         tile_overlap=self.encode_tile_overlap).latent
```

`vae.encode` → `slicing_encode` 内部处理时间维度：将片段切分为 `slicing_sample_min_size` 帧的块（由 `vae.slicing.split_size` 配置，默认 4），并以因果卷积缓存处理 —— 首帧使用 `MemoryState.INITIALIZING`，其余块使用 `MemoryState.ACTIVE`。这在保留整个片段时间上下文（旧循环因逐帧重新初始化而丢弃）的同时，移除了冗余的 `empty_cache`/`gc` 开销。

### 2.2 左上角分块伪影（TensorRT 编码器）

TensorRT VAE 编码器将填充后的帧切分为 256px/512px 的 tile，并用余弦羽化与 DC 偏移校正拼接 latent。每个 tile 的左上角位于 tile 边缘 —— 编码器感受野在此被截断 —— 且紧邻 replicate 填充区域，其非自然（边缘重复）内容污染编码器的中间特征，产生可见的左上角模糊/噪点带。

已尝试的缓解措施及其测得的左上角 latent 标准差（中心 ≈ 1.0）：

| 措施 | 结果 |
|---|---|
| 无外围填充 | 1.70 |
| `reflect` 填充 | 黑块（5D 不支持 / 已回退） |
| 零填充 | 1.34 |
| Replicate 填充（四边） | 1.27 |
| 重叠 96 / 128 / 192px | 无变化 |
| 边缘丢弃 | 无变化 |
| 余弦羽化 | 无变化 |
| DC 偏移校正 | 无变化 |
| 半 tile 外围填充 | 已尝试 |

该伪影无法降至 ~1.27–1.36 以下，因此暂停 TensorRT 编码器，编码回退至 FP16 VAE。缓解代码（半 tile 填充、`set_input_shape` 后的 `synchronize`）保留在 `src/core/trt_encoder.py` 中供后续工作使用。
